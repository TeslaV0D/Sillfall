# Manuelle Checkliste M14 – Release

Automatisch geprüft:

- **Core-Tests:** Paketidentität, Version, Protokoll, Startup-Task, Fähigkeiten, Datenschutzerklärung,
  winget-Manifest (Hashes bleiben Platzhalter).
- **CI:** Job `package` baut bei jedem Pull Request das MSIX für x64 und ARM64, signiert es mit einem
  Entwicklungszertifikat und lädt die Pakete als Artefakte `msix-x64` und `msix-ARM64` hoch.

Die Store-Zertifizierung selbst steht am Ende dieser Liste. Vorher den Namen reservieren.

## 1. Name

- [ ] In Partner Center einen Namen reservieren. „Weatherly“ ist der Arbeitstitel: im Mac App Store gibt es
      bereits eine Wetter-App dieses Namens (ADR-0017). Einen Namen nicht raten, sondern einen freien nehmen.
- [ ] Danach die Repository-Variablen setzen: `WEATHERLY_PACKAGE_NAME`, `WEATHERLY_PACKAGE_PUBLISHER`
      (beginnt mit `CN=` und ist das Subjekt des Signierzertifikats), `WEATHERLY_PUBLISHER_DISPLAY_NAME`.
- [ ] `AppInfo.Name` und `<Product>` in `Directory.Build.props` auf denselben sichtbaren Namen stellen.
      Das Schema `weatherly://` und die Startup-Task-Id bleiben.

## 2. Paket auf dem eigenen PC

Artefakt `msix-x64` (oder der Release-Entwurf eines Tags `v0.1.0`):

- [ ] Das Zertifikat `Weatherly_0.1.0.0_x64.cer` unter „Vertrauenswürdige Personen“ des aktuellen Benutzers
      installieren. Querladen ist erlaubt (Entwicklermodus oder Sideload).
- [ ] `Weatherly_0.1.0.0_x64.msix` installieren. Fehlt die Windows App Runtime, zuerst die Pakete im Ordner
      `Dependencies` installieren. Die App startet, das Symbol liegt im Infobereich, Regen läuft.
- [ ] Einstellungen, Info: der Link „Datenschutzerklärung“ öffnet die englische Erklärung.
- [ ] Deinstallieren über „Apps“ entfernt die App. Das Entwicklungszertifikat wieder entfernen.

Auf einem ARM64-Gerät dasselbe mit `msix-ARM64`, wenn eines da ist.

## 3. Signierung für die Veröffentlichung

Für ein Paket, das ohne Entwicklungszertifikat installiert:

- [ ] Azure Artifact Signing einrichten (Nachfolger von Trusted Signing). Secrets:
      `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_ARTIFACT_SIGNING_ENDPOINT`,
      `AZURE_ARTIFACT_SIGNING_ACCOUNT`, `AZURE_ARTIFACT_SIGNING_CERTIFICATE_PROFILE`.
      Das Zertifikats-Subjekt ist `WEATHERLY_PACKAGE_PUBLISHER`.
- [ ] Tag `v` plus die Version aus `Directory.Build.props` setzen (jetzt `v0.1.0`). Der Job legt einen
      Release-Entwurf an. Darin liegt das öffentlich signierte `Weatherly_<Version>_<Arch>.msix`.
- [ ] Dieses Paket installiert ohne das Entwicklungszertifikat.

## 4. Store

Screenshots selbst aufnehmen, PNG, mindestens 1366×768. Vorschläge: Regen über ein paar Fenstern, Schnee,
Einstellungsfenster, Flyout, ein Besucher. Nichts von der Referenz-App.

- [ ] Unsigniertes Paket (`*.unsigned.msix`, gebaut mit der reservierten Identität) in Partner Center hochladen,
      je x64 und ARM64.
- [ ] Texte aus `docs/store/listing.md` einsetzen, Datenschutz-URL und Support-URL unverändert lassen.
- [ ] Altersfreigabe ausfüllen. Erwartung: 3+.
- [ ] Zertifizierung besteht. Ablehnungen hier notieren.

## 5. winget

Erst wenn das öffentlich signierte Paket im Release liegt:

- [ ] `wingetcreate` über die Release-Dateien laufen lassen und die Platzhalter-Hashes
      (64 Nullen) in `winget/TeslaV0D.Weatherly/` ersetzen.
- [ ] Pull Request gegen `microsoft/winget-pkgs`, Pfad `manifests/t/TeslaV0D/Weatherly/<Version>/`.
