# Manual checklist M14 – Release

Checked automatically:

- **Core tests:** package identity, version, protocol, startup task, capabilities, privacy policy,
  winget manifest (hashes stay placeholders).
- **CI:** the `package` job builds the MSIX for x64 and ARM64 on every pull request, signs it with a
  development certificate, and uploads the packages as artifacts `msix-x64` and `msix-ARM64`.

Store certification itself is at the end of this list. Reserve the name first.

## 1. Name

- [ ] Reserve **Sillfall** in Partner Center. The earlier working title “Weatherly” collides with an
      existing weather app (ADR-0017). If Sillfall is taken, do not guess: pick a free name and rename.
- [ ] Then set the repository variables: `SILLFALL_PACKAGE_NAME`, `SILLFALL_PACKAGE_PUBLISHER`
      (starts with `CN=` and is the subject of the signing certificate), `SILLFALL_PUBLISHER_DISPLAY_NAME`.
- [ ] Only if the reserved name differs: set `AppInfo.Name` and `<Product>` in `Directory.Build.props` to the
      same display name. The scheme `sillfall://` and the startup task id stay.

## 2. Package on your own PC

Artifact `msix-x64` (or the release of a tag `v0.1.0`):

- [ ] Install the certificate `Sillfall_0.1.0.0_x64.cer` into “Trusted People” of the current user.
      Sideloading is allowed (developer mode or sideload).
- [ ] Install `Sillfall_0.1.0.0_x64.msix`. If the Windows App Runtime is missing, install the packages in the
      `Dependencies` folder first. The app starts, the icon is in the notification area, rain runs.
- [ ] Settings, About: the “Privacy policy” link opens the English policy.
- [ ] Uninstalling via “Apps” removes the app. Remove the development certificate again.

Repeat with `msix-ARM64` on an ARM64 device, if one is available.

## 2b. Setup .exe (ADR-0018)

Artifact `installer-x64` (or the release of a tag `v0.1.0`), on a PC without a development build:

- [ ] `Sillfall-Setup-0.1.0-x64.exe` starts. SmartScreen warns (not signed yet): *More info* > *Run anyway*.
- [ ] No UAC prompt for the default per-user install. The setup is in English or German, matching Windows.
- [ ] After setup Sillfall starts, the tray icon is there, rain runs. Start menu has a “Sillfall” entry.
- [ ] A `sillfall://` scene link (Settings, Templates, share) opens the app.
- [ ] Turn autostart on in Settings, Advanced; sign out and in: Sillfall starts.
- [ ] Run the setup again while Sillfall runs: it asks to close the app and updates without errors.
- [ ] Uninstall from Settings > Apps: files, Start menu entry, `HKCU\Software\Classes\sillfall` and the Run value
      `Sillfall` are gone. `%LOCALAPPDATA%\Sillfall` stays.
- [ ] Same with `Sillfall-Setup-0.1.0-arm64.exe` on an ARM64 device, if one is available.

## 2c. SignPath (signing the setup, ADR-0018)

- [ ] Release `v0.1.0` is public (SignPath only accepts projects that are already released).
- [ ] Turn on two-factor authentication on GitHub (and later on SignPath).
- [ ] Apply at https://signpath.org (open source code signing). Point to the README section “Code signing policy”.
- [ ] After acceptance, in SignPath: add the trusted build system “GitHub.com” and link it to the project, install
      the SignPath GitHub App for this repository, and create the artifact configuration from
      `tools/installer/signpath-artifact-configuration.xml`. Signing policy: manual approval.
- [ ] In GitHub (Settings > Secrets and variables > Actions): secret `SIGNPATH_API_TOKEN` (user with submitter
      rights), variables `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT_SLUG`, `SIGNPATH_SIGNING_POLICY_SLUG`.
- [ ] Bump the version, tag it, approve the signing request in SignPath. The release notes say the setup is signed.
- [ ] Downloaded setup: Properties > Digital Signatures shows SignPath Foundation.

## 3. Signing for publication

For a package that installs without the development certificate:

- [ ] Set up Azure Artifact Signing (successor of Trusted Signing). Secrets:
      `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_ARTIFACT_SIGNING_ENDPOINT`,
      `AZURE_ARTIFACT_SIGNING_ACCOUNT`, `AZURE_ARTIFACT_SIGNING_CERTIFICATE_PROFILE`.
      The certificate subject is `SILLFALL_PACKAGE_PUBLISHER`.
- [ ] Push tag `v` plus the version from `Directory.Build.props` (now `v0.1.0`). The job publishes a
      release containing the publicly signed `Sillfall_<Version>_<Arch>.msix`.
- [ ] This package installs without the development certificate.

## 4. Store

Take screenshots yourself, PNG, at least 1366×768, with the real desktop visible (the images in
`docs/media/` are overlay-only renders, not store screenshots). Suggestions: rain over a few windows, snow
on window tops, the settings window (Effects page), the tray flyout, a visitor. Nothing from the reference
app and no other companies’ names, logos or artwork.

- [ ] Upload the unsigned package (`*.unsigned.msix`, built with the reserved identity) to Partner Center,
      x64 and ARM64.
- [ ] Paste the texts from `docs/store/listing.md`; keep the privacy and support URLs unchanged.
- [ ] Fill in the age rating. Expected: 3+.
- [ ] Certification passes. Note rejections here.

## 5. winget

Only once the publicly signed package is in the release:

- [ ] Run `wingetcreate` on the release files and replace the placeholder hashes (64 zeros) in
      `winget/TeslaV0D.Sillfall/`.
- [ ] Pull request against `microsoft/winget-pkgs`, path `manifests/t/TeslaV0D/Sillfall/<Version>/`.
