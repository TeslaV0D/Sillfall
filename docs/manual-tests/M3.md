# Manuelle Checkliste M3 – Engine und Tooling

M3 bringt den Render-Loop, die Kalibrier-Tropfen als Test-Effekt, die Sandbox und FrameDump.
Echte Wettereffekte folgen ab M4.

Automatisch geprüft ist schon (CI):

- Engine: fester Zeitschritt, deterministisch, unabhängig von der Framerate, 0 Allokationen im Loop,
- live auf Windows: über 60 fps auf dem Software-Renderer, 0 Bytes Allokation pro Frame, der Loop
  stoppt nach dem Abschalten von selbst,
- Tropfen liegen im Desktop-Screenshot auf der Oberkante des App-Fensters,
- Sprite-Formen, Blending, Direct2D und Golden-Images mit WARP.

## 1. Kalibrier-Tropfen in der App

```bash
dotnet run --project src/Weatherly.App -p:WindowsPackageType=None
```

„Calibration drops“ einschalten, Testmuster aus.

- [ ] Tropfen fallen über alle Monitore und bleiben auf Fensteroberkanten liegen.
- [ ] Fenster mit liegenden Tropfen verschieben: Die Tropfen wandern mit.
- [ ] Fenster kräftig hin und her schütteln: Die Tropfen fallen ab.
- [ ] Fenster schließen oder minimieren: Die Tropfen darauf fallen auf den Boden über der Taskleiste.
- [ ] Bewegung wirkt flüssig, kein Ruckeln bei 60 Hz, bei einem 120/144-Hz-Monitor bitte notieren.
- [ ] Tropfen ausschalten: Nach etwa 3 Sekunden sind alle weg, danach GPU der App im Task-Manager bei 0 %.
- [ ] Check „Window tracking“ und alle anderen Checks bleiben `OK` („Check again“).

## 3. Sandbox

```bash
dotnet run --project tools/Weatherly.Sandbox
```

- [ ] Ein Fenster mit dunklem Fake-Desktop, drei Fake-Fenstern und fallenden Tropfen erscheint.
- [ ] Fake-Fenster lassen sich ziehen, das angeklickte kommt nach vorn.
- [ ] `S` zeigt die Oberflächen-Linien, `D` schaltet die Tropfen, `N` öffnet ein Fenster, `Entf` schließt eins.
- [ ] Pfeil links/rechts ändert den Wind, die Tropfen treiben sichtbar.
- [ ] Sandbox-Fenster vergrößern: Inhalt passt sich an.

## 4. FrameDump

```bash
dotnet run --project tools/Weatherly.FrameDump -- --out framedump
```

- [ ] Im Ordner `framedump` liegen PNGs pro Szene und je ein `*-sheet.png`.
